# MiniMind 本地复现计划

创建日期：2026-10-09（Asia/Shanghai）。

## 目标与当前状态

在个人电脑上完成 MiniMind-3 Dense 的从零预训练、全参数指令微调（SFT）和对比评测。每完成一个可验证的小步骤，就把代码、配置和阶段成果推送到自己的 GitHub。

- 个人仓库：https://github.com/MrMo5235/minimind
- 实验分支：`reproduce`
- 原项目：https://github.com/jingyaogong/minimind
- 固定起点：见 [UPSTREAM.md](UPSTREAM.md)。
- 用户提供的显卡：NVIDIA GeForce RTX 4060，8188 MiB 显存。
- 当前工作环境：Windows / PowerShell。
- 尚未验证：系统内存、磁盘空间、显卡驱动、Python、PyTorch、CUDA 可用性及训练吞吐量。
- 当前阶段：仓库与计划记录；尚未安装训练依赖、下载数据或启动训练。

先完成 Dense 主线，之后按需求逐项增加 LoRA、DPO 或 MoE 实验。

## 阶段与验收

| 阶段 | 工作 | 验收标准 | GitHub 成果与阶段标签 |
| --- | --- | --- | --- |
| 00 仓库与计划 | Fork、连接 origin/upstream、创建 reproduce 分支、固定代码版本 | 分支可推送，计划与版本记录可在远端查看 | 本目录；`stage-00-plan` |
| 01 环境 | 创建独立环境，选择适配设备的 PyTorch，检查 GPU 和依赖 | 模型完成前向、反向及参数更新 | 环境检查脚本、版本清单、检查报告；`stage-01-env` |
| 02 数据 | 下载 mini 数据，校验格式，固定验证划分和测试问题 | 数据可加载，训练/验证分离，记录文件校验值 | 下载说明、数据统计、SHA256、划分规则、评测问题；`stage-02-data` |
| 03 小规模训练 | 预训练和 SFT 小数据试跑，检查保存、重载和断点续训 | Loss 有限、参数更新、保存与恢复成功 | 小规模配置、日志和结果；`stage-03-smoke` |
| 04 性能测试 | 测试候选 batch size、序列长度和精度 | 有稳定吞吐量、显存峰值和完整训练耗时估算 | 性能表及最终训练配置；`stage-04-profile` |
| 05 正式预训练 | 从随机初始化开始使用选定配置训练 | 完成计划步数，权重可加载，保存验证集指标 | 配置、日志、曲线、续写样例、报告；`stage-05-pretrain` |
| 06 正式 SFT | 从本次预训练权重继续进行指令微调 | 训练完成，按对话模板生成回答 | 配置、日志、曲线、固定问题输出、报告；`stage-06-sft` |
| 07 对比评测 | 比较自己的预训练模型、SFT 模型与官方同版本模型 | 同一套评测条件下得到可重复的指标和差异分析 | 评测脚本、结果表、失败案例、总结；`stage-07-eval` |

本计划从阶段 04 起单列性能测试，因此标签编号以本文件为准。
小规模试跑仅验证训练流程，阶段 07 完成后才总结正式复现效果。

## RTX 4060 候选配置

以下配置只是起点，尚未进行本机测试。正式训练前根据阶段 04 的结果调整。

| 参数 | 预训练 | SFT |
| --- | --- | --- |
| hidden_size | 768 | 768 |
| num_hidden_layers | 8 | 8 |
| use_moe | 0 | 0 |
| batch_size | 4 | 2 |
| accumulation_steps | 64 | 8 |
| 单卡有效批大小 | 256 | 16 |
| max_seq_len | 340 | 768 |
| dtype | 检查 BF16 支持后选择 | 与预训练一致 |
| num_workers | 先用 0 | 先用 0 |
| seed | 42 | 42 |
| use_compile | 先用 0 | 先用 0 |
| 数据文件 | pretrain_t2t_mini.jsonl | sft_t2t_mini.jsonl |

小规模检查先使用 `accumulation_steps=1`，确保短试跑确实执行参数更新。
正式训练的轮数、学习率、保存间隔和数据规模在性能测试后明确写入配置。

保持模型结构和原 Tokenizer 一致，以便复用权重并进行同版本比较。预训练与 SFT 的模型结构必须一致。
减小 batch size、增加梯度累积只能保持有效批大小；浮点误差、调度实现等仍可能导致结果差异，不能据此声称训练完全等价。

## 每一步的提交与推送

1. 确定本步目标和验收方式。
2. 完成工作，检查结果，更新实验记录。
3. 使用 `git diff` 检查内容，只暂存本步需要的文件。
4. 提交并推送到 `origin/reproduce`。
5. 核对远端分支提交；整阶段通过验收后再创建并推送阶段标签。

提交示例：`docs: record reproduction plan`、`env: add GPU environment report`、`exp: record pretraining smoke run`。
失败的实验也保存错误信息、原因分析和修复结论，避免只保留成功结果。

GitHub 日常提交保存代码、配置、文档、曲线、汇总指标和精简样例。
完整数据、下载的模型、训练权重、优化器检查点和本地虚拟环境不进入普通 Git 提交；开始下载前补充对应忽略规则。
需要共享大文件时，另行确定存储位置，在报告中提供链接和 SHA256。

## 实验记录与评测约定

每次运行使用 [EXPERIMENT_TEMPLATE.md](EXPERIMENT_TEMPLATE.md) 记录：

- 上游起点和本次代码 commit；运行时的未提交改动另行说明。
- GPU、驱动、系统内存、Python/PyTorch 等依赖版本。
- 数据来源、SHA256、样本数、划分方式、随机种子。
- 工作目录、完整命令、模型参数、batch size、梯度累积、精度、学习率、步数及轮数。
- 训练 Loss、验证指标、稳定吞吐量、显存峰值、实际耗时及输出样例。
- 权重及断点检查点位置、校验值、相对原配置的偏离和结论。

性能测试排除初始化和预热时间，记录完整数据加载与训练的稳定速度，再估算正式训练时长。
评测固定问题、随机种子、生成长度和采样参数。原 `eval_llm.py` 会随机选择生成种子，正式评测需补充固定种子的可重复入口。
预训练使用文本续写评测，SFT 使用对话模板评测；不同模板或不同目标下的 Loss 不直接作为同一指标比较。
官方模型属于参考基线，不替代自己的从零训练；不能仅凭几个回答相似就声称复现了官方效果。
