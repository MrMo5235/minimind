# 首次训练前后生成对比

日期：2026-10-21。推理脚本：`scripts/compare_pretrain.py`；详细用法见 `reproduction/COMPARE_PRETRAIN.md`。

## 条件

- seed=42 的初始化模型按当前源码重建，不是训练开始前保存的原始权重快照。
- 训练后使用 `out/smoke/pretrain_smoke_768.pth`（只训练 128 条、64 步）。
- 两边同结构、同 tokenizer、同提示、BF16、cuda:0、greedy，repetition_penalty=1.0。
- 此次验证每边最多生成 16 个新 token，用户交互配置默认上限为 64。
- 权重 SHA256 与首次训练记录一致，未更新权重。

## 运行与观察

`samples.jsonl`：连续两次输入“机器学习是一种”。初始化基线输出杂乱且重复的片段，训练后输出连续逗号。两次运行各自的生成 token ID 完全一致。

`interactive.jsonl`：通过标准输入发送“今天早上，我打开窗户，看到”和 `/exit`。验证交互读入、两边流式生成、JSONL 保存及退出。训练后样例主要为逗号和换行，同样尚未形成有用续写。

`verification.json`：配置参数、同提示重复生成、交互记录、token 上限和权重校验值的检查结论。

当前观察只能说明 128 条试跑模型还缺少可用的生成能力，不能否定已核验的参数更新，也不能替代独立验证集评估。greedy 模式下的重复是保留的实际结果；若改为采样，需两边保持相同设置，不能挑选个别输出宣称效果。

本次固定提示只是演示提示，未做训练集重合检查。未来正式训练前应保存初始权重快照，并使用固定、独立的测试提示及验证集指标。

用户后续交互输入默认保存到被 Git 忽略的 `out/comparisons/`。这里提交的只有本次预设的演示输入与输出，不会自动提交个人交互记录。
